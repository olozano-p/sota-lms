# ADR-002 · PostgreSQL 16 through Drizzle, PGlite in tests

**Date** 2026-09-11 · **Status** accepted

## Decision

PostgreSQL 16 is the database, reached through `pg` and Drizzle ORM (`pg-core`). Migrations are
generated by `drizzle-kit generate` into `drizzle/` and applied by `src/db/migrate.ts` (also the
explicit deploy step). Primary keys are UUID v7 generated in the app (`uuidv7`), timestamps are
`timestamptz`, JSON payloads are `jsonb`, arrays are native. Tests open an in-memory PGlite through
the same Drizzle schema when `DATABASE_URL=pglite://memory`.

## Why

- The schema wants `jsonb` (block payloads, webhook events), `uuid[]` (quiz answers) and
  concurrent writers (Docker image may run several replicas behind a proxy); SQLite would fight
  all three.
- Postgres is what a small organisation's VPS already has or can run in one container; the spec
  fixes it.
- PGlite lets `pnpm test` run the webhook and access tests without Docker, in the real dialect.

## Consequences

- `docker compose -f compose.dev.yml up` is the one-command local setup; there is no file-based fallback.
- Rejected: SQLite (see above), Prisma, `drizzle-kit push` (unreviewed drift), an ORM-less
  approach (the schema is the documentation).
- Never edit an applied migration; superseding changes get a new one.
