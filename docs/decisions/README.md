# Architecture decision records

One file per decision, numbered, dated, never rewritten: a superseding decision gets its own file
and links back. Shape: **Decision** · **Why** · **Consequences** (what becomes easier, what we
give up, what must not be re-proposed).

A record explains the architecture or how the project is run. Feature details and visual choices
live in the documents they shape (`docs/spec.md`, `docs/DESIGN.md`, `docs/theming.md`), so the
numbering has gaps.
